# Preprocessing Report

_Generated by `scripts/preprocess_dataset.py` from `data/interim/cleaned_pump_dataset.csv`._

Output: `data/processed/preprocessed_pump_dataset.csv` — **7,210 rows × 123 columns**.

## What was done and why
| Operation | Columns created | Justification |
|---|---|---|
| Kept original engineering units | all 11 sensor columns unchanged | KBS rules and engineers reason in mm/s, °C, bar, A — normalising them away would make rules unreadable. |
| Joined nameplate data from the asset register | `Rated_*`, `Nominal_Suction_bar_a` | Pumps range from 20 to 900 m³/h; absolute thresholds cannot work across them. Register data is known a priori, so it does not leak labels. |
| Relative performance features | `Flow_Pct_Rated`, `Head_Pct_Rated`, `Current_Pct_Rated`, `Speed_Deviation_Pct`, `Differential_Pressure_bar`, `Current_per_Flow_Index` | Express each reading as a position on its own pump's curve — the way pump engineers diagnose. |
| Derived features from imputed inputs → <NA> | all relative features above | Schema validation found that per-pump median imputation can create impossible combinations (imputed suction above measured discharge in dry-running records → negative head). Imputed sensor values stay in the sensor columns (flagged), but nothing is *derived* from them. |
| Vibration severity zone | `Vibration_Zone` (A–D) | ISO 10816-3-style zone boundaries 1.4 / 2.8 / 4.5 mm/s RMS (verify against the standard before real use). |
| Date features | `Obs_Year/Month/Quarter`, `Pump_Age_Years`, `Days_To_Maintenance`, `Has_Maintenance_Event`, `Hours_Since_Last_Maintenance` | Age and running hours since the last intervention are classic wear indicators. Only *earlier* events are used, so there is no look-ahead. |
| Sensor-derived symptoms | `sens_*` (1/0/<NA>) | Converts numbers into the symbolic evidence the KBS consumes. **<NA> when the source value was imputed** — evidence is never derived from a guess. |
| Operator-recorded symptoms | `obs_*` (1/0/<NA>) | Multi-hot of `Symptom_Keys`; <NA> when symptoms were not recorded (≠ no symptoms). |
| Ordinal encodings | `Severity_Level` 0–4, `Priority_Level` 0–4 | Natural order; `Unknown` → <NA>, not a fake level. |
| One-hot encodings | `Pump_Type__*`, `Manufacturer__*`, `Diagnostic_Status__*` | Nominal categories, few levels. |
| Label codes | `Fault_Code`, `KBS_Fault_ID`, `Is_Fault` | Link each record to the existing KBS fault IDs in `../data/faults.csv`. |
| Group-aware stratified split | `Partition` | `StratifiedGroupKFold(5)` on `Fault_Type`, grouped by `Pump_ID`: fold 0 → test, fold 1 → validation, rest → train. Records of one pump (and therefore of one fault episode / maintenance event) never appear in two partitions. |
| Standardisation | `z_*` for 12 continuous features | Only for optional distance-based evaluation. Mean/std fitted on **train only** (`scaler_params.json`) to avoid leakage. |

### Not done (deliberately)
- No normalisation of the original sensor columns; no scaling of flags or ordinal codes.
- No model training, no oversampling, no feature selection — those belong to a later, separate evaluation and would otherwise leak test information.
- Per-pump medians used during cleaning are computed within a pump; because the split is by pump, they never mix train and test pumps. The only cross-pump statistic is the global-median fallback for pumps with no observed value (not triggered in this run unless reported in the cleaning log).
