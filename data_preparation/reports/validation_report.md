## C. Evaluation against the generation log (synthetic ground truth)
Because the dataset is synthetic, the pre-corruption reference and a cell-level log of every injected problem exist. The cleaning script never read them; they are used here only to score it. **This kind of scoring is impossible with real plant data.**

- Reference records: 7,210 · cleaned records: 7,210 · reference IDs missing from cleaned: **0** · extra IDs: **0**
- Exact duplicates injected: 108 · still present: **0**
- Near-duplicates injected: 36 · removed and recorded in Merged_Record_IDs: **36**
- Corrupted cells evaluated: 7,602 · wrong / undetected: **0**
- Genuine (uncorrupted) values wrongly nullified as errors: **0**
- Fault labels differing from reference: 49 — of which not explained by a missing source label: **0**

**How to read a perfect score.** The same project wrote the corruption step and the cleaning rules, and the cleaning rules were designed from the quality report of this very file. A score of zero errors therefore shows that every *catalogued* problem type is handled correctly and that no genuine value was damaged — it does **not** show that the pipeline would handle unseen problems in real plant data (new unit spellings, new label variants, sensor drift, mis-labelled faults). Unmapped values are listed in the cleaning report precisely so such cases surface on new data.
