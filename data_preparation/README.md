# Data Preparation Pipeline — Centrifugal Pump KBS (CT-359)

A complete, reproducible data-preparation workflow that runs **before** knowledge-base development:
synthetic data collection → deliberate data-quality problems → quality assessment → cleaning →
preprocessing → exploratory analysis → validation.

> **Synthetic data.** Every record here is generated by `scripts/generate_dataset.py` (seed 359). It is not plant
> data and must not be presented as factory records. See `reports/dataset_description.md`.

This folder is self-contained. It does **not** read or modify the existing KBS (`../data`, `../src`, `../tests`,
`../requirements.txt`).

## How to run (Windows PowerShell, VS Code terminal)
Requires **Python 3.11 or newer** (tested with 3.11.9). All commands are run from the `data_preparation` folder.

### First time
```powershell
cd C:\path\to\Centrifugal_Pump_KnowledgeBasedSystem\data_preparation
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
.\run_pipeline.ps1
```
If PowerShell refuses to run `Activate.ps1` or `run_pipeline.ps1` ("running scripts is disabled"), allow scripts
for the current window only and retry:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```
In VS Code: `Ctrl+Shift+P` → **Python: Select Interpreter** → choose `data_preparation\.venv` (needed to open the
notebooks with the right kernel).

### Later runs
```powershell
cd C:\path\to\Centrifugal_Pump_KnowledgeBasedSystem\data_preparation
.\.venv\Scripts\Activate.ps1
.\run_pipeline.ps1                   # reuse the existing raw file
.\run_pipeline.ps1 -SkipNotebooks    # faster: scripts only
.\run_pipeline.ps1 -RegenerateRaw    # rebuild the raw file (identical bytes, same seed)
```

### Running steps individually
```powershell
python scripts\generate_dataset.py          # refuses to overwrite an existing raw file (use --force)
python scripts\data_quality_analysis.py
python scripts\clean_dataset.py
python scripts\preprocess_dataset.py
python scripts\exploratory_analysis.py
python scripts\validate_dataset.py
python scripts\build_notebooks.py
```
Each step reads only the previous step's output, so a later step can be re-run on its own.

## Reproducibility and safety
- Fixed seed (`common.SEED = 359`); regenerating produces a byte-identical raw file (verified by SHA-256).
- The raw file is **write-once**: the generator will not overwrite it without `--force`, and the cleaning script
  refuses to run if the raw file's checksum no longer matches `data/raw/CHECKSUMS.sha256` (i.e. it was edited
  by hand).
- Generation, cleaning and preprocessing are separate scripts; no CSV is edited manually.
- The cleaning script never reads `data/generation_log/`; only `validate_dataset.py` uses it, to score the
  cleaning after the fact.
- All paths are resolved relative to `data_preparation/`; nothing outside this folder is written.

## Main cleaning decisions (details in `reports/cleaning_report.md`)
- Exact duplicates dropped; re-keyed copies of the same pump/date merged; repeated maintenance kept.
- Units converted to °C, bar(a), m³/h; dates to ISO 8601 (DD/MM proven from the data); 79 fault-label spellings → 12.
- Physically impossible values nullified; statistical outliers **kept** (they are fault evidence); only extremes
  contradicted by their own Normal record are treated as entry errors.
- Sensors: per-pump median imputation, flagged; operating hours: time interpolation; equipment attributes:
  per-pump mode, verified against the asset register.
- Missing fault labels, causes, severities and priorities → `Unknown`, never guessed.
- Preprocessing never derives a symptom from an imputed value (`sens_*` = `<NA>`).

## Limitations
- The data is synthetic; every EDA pattern reflects generator assumptions, and the perfect cleaning score shows
  only that the *catalogued* problem types are handled (the same team wrote the corruption and the cleaning).
- Single-fault records, simplified physics, no sensor drift or transients.
- Thresholds (vibration zones, temperatures, 85 dB(A)) are documented engineering defaults, not OEM limits.
- Median imputation cannot recover fault-driven values; imputed rows are flagged and should be excluded from
  evidence.
