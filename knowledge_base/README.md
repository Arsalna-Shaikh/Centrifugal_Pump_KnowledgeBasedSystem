# Structured Knowledge Base (KR-1)

The structured knowledge base for the Centrifugal Pump KBS (CT-359). It implements the model in
`knowledge_acquisition/ka3_final_knowledge_model.md` with the four KR-1 corrections, listed in `kb_meta.json`.

The legacy knowledge base in `data/`, the old engine (`src/inference_engine.py`) and the Streamlit app are
**unchanged**. The new inference engine is a later stage.

## Two separate quality measures (correction 4)
- **`support_level` / `validation_status`: how good is the knowledge?** This depends on the sources behind it:
  - **Strong:** a read independent source.
  - **Moderate:** a read manufacturer or trade source.
  - **Unvalidated:** project sources only.
  - **Disputed:** contradicted by an independent source.
  - **Definitional:** true by definition or design.
- **`likelihood` on a rule's conclusion: how diagnostic is the pattern when it matches?** One of `confirmed`, `likely`
  or `possible`.

A rule can describe a characteristic pattern (`likely`) while resting on unvalidated knowledge, and the reverse.
The display policy in `kb_meta.json` caps unvalidated rules at "possible" when results are shown. It does not
change the stored likelihood.

## Measurement bases (correction 3)
Each threshold declares its `basis`:
- `absolute`: engineering units;
- `pct_rated`: percentage of an `equipment_parameters` rated value;
- `pct_baseline`: percentage of a healthy-baseline value.

Some thresholds have **no value**. Their value has not been sourced, and none is invented. Every numeric threshold
is `Unvalidated`, because KA-2 found no source for any value.

## Provenance rules enforced by the validator
- Every relationship, threshold, test, hazard class and safety rule has `source_ids` and a `source_locator`.
- **Cost and downtime** (`cost_class`, `downtime_class` on faults and actions) are qualitative classes copied from
  the legacy KB (`P-01`) and are all **Unvalidated**. A record that merges legacy records with different classes
  holds their range (e.g. `MEDIUM-HIGH`). A record with no legacy counterpart is `UNKNOWN`; no value is invented and
  there are no monetary or time figures. The validator checks every inherited value against `data/`.
- **Maintenance priority** is not stored per record. It is a policy in `kb_meta.json` (Unvalidated, `P-05`)
  that the decision-support layer applies to each recommended action. It is separate from hazard class, cost and
  downtime, and it never changes the diagnosis.
- **Strong** requires a *read* independent source. **Moderate** requires a *read* manufacturer or trade source.
  **Disputed** requires a read independent source.
- A rule's support may not be stronger than the weakest relationship it uses. A rule may not use a Disputed
  relationship as positive evidence.
- If a rule depends on an unvalidated *discriminator* assumption, the rule must be Unvalidated.
- Every legacy component, symptom, fault, action and rule ID, and every legacy weight line, must be mapped (or
  explicitly retired). Mapped weights must point to the corresponding new fault and symptom.

## Validate
```powershell
python knowledge_base\validate_kb.py
```
This needs only the Python standard library. It reads `data/` read-only for the legacy cross-checks, writes
`VALIDATION_REPORT.md`, and exits with code 1 on any error.
